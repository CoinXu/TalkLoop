一、产品概述

1.1 产品定位

一款面向"词汇有积累但听说能力薄弱"的英语学习者的跟读训练应用。


1.2 目标用户

有一定英语词汇基础（1000–7000 词）
阅读能理解，但听力反应慢、口语说不出
希望把"认得的词"变成"听得懂、说得出的词"

1.3 V1 功能清单

编号	功能	说明
F0	词库系统	词表、语料、用户词库三层架构，含自动标注算法
F1	水平评估	了解用户的英语水平，建立初始词库
F2	单词激活	将用户的阅读词汇转化为听说词汇
F3	听读功能	听原音 → 跟读 → 对比反馈的完整练习

2.2 词表层设计

2.2.1 数据来源：SUBTLEXus

词频数据基于 SUBTLEXus（基于 5100 万词影视字幕语料），选择它的原因：


维度	说明
语料来源	电影和电视剧字幕，天然口语化
词频含义	反映真实口语/日常英语的使用频率
覆盖范围	~74,000 个词形
附加指标	上下文多样性（Lg10CD），判断词是否"通用"

SUBTLEXus 关键字段说明：


字段	官方定义	在产品中的用途
Word	词形（大写开头表示更常以大写出现）	基础数据
FREQcount	在 5100 万词语料中出现的总次数	计算合并后词频
CDcount	出现在多少部影视作品中（上限 8388）	计算上下文多样性
FREQlow	以小写形式出现的次数	判断是否为专有名词
CDlow	以小写形式出现在多少部作品中	辅助判断
SUBTLWF	每百万词频率（标准化词频）	难度分级的主指标
Lg10WF	log10(FREQcount+1)	难度分级：用于阈值查询
SUBTLCD	出现在百分之多少的影视作品中（0-100%）	展示用
Lg10CD	log10(CDcount+1)	过滤偏门词：用于阈值查询

官方转换表：


Lg10WF 与 SUBTLWF 的对应关系：


Lg10WF	SUBTLWF	每百万词出现次数
1.00	0.2	0.2 次（极低频）
2.00	2	2 次
3.00	20	20 次
4.00	200	200 次
5.00	2000	2000 次（极高频）

Lg10CD 与 SUBTLCD 的对应关系：


Lg10CD	SUBTLCD	出现在多少部作品中
0.95	0.1%	~8 部（极偏门）
1.93	1%	~85 部
2.92	10%	~839 部
3.92	100%	8388 部（所有作品）

Level 4	< 1.30	< 2	低频词，高阶区	~1000-1200

2.2.3 过滤偏门词

用 Lg10CD 做过滤，基于官方转换表：


Lg10CD	SUBTLCD	出现在多少部作品中	处理
≥ 2.92	≥ 10%	839+ 部	通用词，保留
1.93 – 2.91	1% – 10%	85 – 839 部	一般，保留但标记
< 1.93	< 1%	< 85 部	排除

出现在不到 1% 的影视作品中（不到 85 部），对学习者来说太偏门。


2.2.4 场景标签

每个词可以有 1–3 个场景标签，用于按主题组织激活任务和课程内容。


场景标签体系：


一级标签	二级标签

职场	会议、邮件、汇报、面试、社交
旅行	机场、酒店、交通、景点、紧急情况
社交	寒暄、闲聊、情感表达、约见

标注方式： 锚点词 + 词向量 + 人工审核（详见第三章算法方案）。


2.2.5 听力陷阱标记

部分词在阅读中容易认识，但听力中容易混淆或反应不过来。


陷阱类型	示例	说明	标注方式
近音混淆	recommend / recognize / recover	发音相近，听时容易混	音素编辑距离算法
连读吞音	want to → wanna	实际发音与拼写差异大	规则匹配（有限列表）
弱读词	the, a, of, to, can	句中弱读时与独立发音差异大	规则匹配（有限列表）

2.4 用户词库层设计

2.4.1 用户词库的生成

用户首次使用时，系统根据 F1 水平评估结果，从词表层中截取一部分词作为该用户的初始词库。


截取规则：


自我描述粗估 → 取 Lg10WF 对应区间的词

初始状态： 所有入库词默认为 🔴 认知词。

2.5 内容生产规范

句子编写原则

DO：


用真实口语表达，像真人说话
句子之间有逻辑关联（同一场景下形成对话感）
覆盖目标词的常见用法和常见搭配
难度在同一课程内保持一致

DON'T：


不用课本体（"How do you do?"、"I am very glad to meet you."）
不用过时表达（"I beg your pardon?"）
不用过于正式的书面语（"We hereby acknowledge receipt of..."）
不在一个句子中堆砌太多生词

音频规范

属性	要求
格式	MP3，128kbps
采样率	44.1kHz
常速语速	140–160 词/分钟
慢速语速	100–120 词/分钟
音量	统一标准化到 -16 LUFS
音色	V1 统一使用一个音色（TTS 合成）

3.3 听力陷阱自动标注

基础：音素编辑距离

把每个词的发音表示为音素序列，计算两个序列之间的归一化编辑距离。


示例：


text
text
recommend  →  R EH K AH M EH N D      （8 个音素）
recognize  →  R EH K AH G N AY Z      （8 个音素）
recover    →  R IH K AH V ER          （6 个音素）

text
text
recommend vs recognize:
  差异：M↔G, EH↔N, N↔AY, D↔Z  → 编辑距离 4，归一化 4/8 = 0.50

  差异：EH↔IH, M↔V, EH N D↔ER  → 编辑距离 5，归一化 5/7 = 0.71

recommend vs furniture:
  差异：几乎全部不同  → 编辑距离 8，归一化 1.0

归一化音素编辑距离 = 编辑距离 / 较长序列的音素数

3.6 意群断句自动标注

实现方式

python
python
def chunk_sentence(text, max_words=12):
    words = text.split()
    if len(words) <= max_words:
        return [text]

    chunks = []
    current = []
    split_tokens = {",", "that", "which", "who", "where",
                    "when", "if", "because", "although",
                    "since", "while", "but", "and"}

    for word in words:
        clean = word.strip(".,!?;:").lower()
        if clean in split_tokens and current:
            chunks.append(" ".join(current))
            current = [word]
        else:
            current.append(word)

    if current:
        chunks.append(" ".join(current))

    return chunks

text

对比播放

按钮	行为
🔊 原音	只播放原音
🎙️ 我的	只播放用户录音
🔊🔁 连续对比	原音 → 用户 → 原音 → 用户，循环 2 次

连续对比是核心体验——用户能直观听到自己和原音的差异。


6.4 反馈系统

反馈一：文本匹配（语音识别 + 文本对比）

实现方式： 调用系统原生语音识别（Web Speech API / 手机系统 ASR），将用户录音转写为文本，与原句做对比。


匹配结果分三档：


等级	条件	显示
✅ 准确	转写文本与原句完全一致或仅有大小写/标点差异	绿色勾
⚠️ 部分匹配	转写文本包含原句 60% 以上的词	黄色三角 + 标出差异词
❌ 偏差较大	转写文本匹配率低于 60%	红色叉 + 显示原文

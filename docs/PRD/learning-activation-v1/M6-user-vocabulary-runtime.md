# M6 user-vocabulary-runtime

## 背景 / 要解决的问题

用户词库层是动态运行时数据，记录每个用户每个词的激活状态、练习结果、SRS 复习、跳过和薄弱发音情况。

## 规则

1. 用户词库由 M5 的词库抽样评估结果从 M2 词表中生成。
2. 初始入库词状态均为认知词 `red`。
3. 每个用户词条记录 `user_id`、`word_id`、`activation_status`、连续正确、总尝试、总正确、最后练习类型、复习时间、复习间隔、失败次数、出现句子、读出次数、薄弱发音、跳过次数、来源。
4. 当前等级激活率达到 70% 时，自动解锁下一批词。
5. 用户跳过某词超过 3 次，标记为回避词并降低出现频率。
6. SRS 间隔：听觉词 1 天后复习；活跃词按 1/3/7/15/30 天递进；复习失败重置。
7. 今日任务和继续学习产生的练习结果使用同一套状态流转、SRS、激活率和解锁规则。
8. 用户完成今日任务后继续学习更多词，不受每日任务量限制；只受可练内容、已解锁等级、句子/音频可用性和保存成功约束。
9. 保存失败不得导致状态错误升级或任务错误完成。
10. 用户词库状态可被后台只读查看；人工修正仅限客服排障场景，必须填写原因。

## 交互

- 用户完成词库抽样评估 -> 系统根据词频边界、置信度和已解锁层级生成用户初始词库。
- 用户练习 -> 系统更新词条状态、复习时间、跳过次数和薄弱标记。
- 用户完成今日任务后继续学习 -> 系统继续按练习结果更新词条状态、复习时间、解锁进度和薄弱标记。
- 用户在“我的”查看词汇激活概览。
- 管理员从用户详情进入用户词库 -> 查看词条状态、练习摘要、来源和异常。
- 管理员修正异常状态 -> 填写原因，系统记录修改前后摘要。

## 视觉 / UI 布局

- 学习端不展示完整表格，用状态计数、趋势、薄弱词表达。
- 后台用户词库以表格展示，支持按状态、来源、薄弱、跳过、到期复习筛选。
- 后台词条详情展示状态流转时间线。

## 边界行为

- 词条源词被归档后，历史状态保留，但不再进入新任务。
- 状态修正不能绕过最后审计要求。
- 用户无词可练时，展示空态并提示重新评估或等待内容补充。
- 用户短时间内激活大量词时，系统必须逐条保存状态流转和规则版本，不能只保存汇总数。
- 运行时字段与内容词表字段分离，避免内容修改覆盖用户状态。

## 验收 checklist

- [ ] 用户词库可由词库抽样评估结果生成。
- [ ] 用户词条记录激活状态、练习、复习、跳过和来源。
- [ ] 当前等级激活率达到 70% 可解锁下一批词。
- [ ] SRS 间隔能按状态和练习结果更新。
- [ ] 今日任务和继续学习产生的结果使用同一套状态流转和 SRS 规则。
- [ ] 高基础用户完成今日任务后，仍可继续推进已解锁词库中的可练词。
- [ ] 保存失败不会导致错误升级或错误完成。
- [ ] 后台可按用户查看词库状态、状态流转和异常词。
- [ ] 后台人工修正用户词库状态必须填写原因并审计。

## 非目标

- 不做用户外部词表导入。
- 不做批量人工改用户词库状态，除非后续客服工具另行定义。

## 管理后台功能

后台必须提供用户词库查询、筛选、状态时间线、异常标记、单词条修正、重算词库、审计。

# M1 admin-foundation

## 背景 / 要解决的问题

v1.0 的词库、语料、评估、练习和用户状态都需要后台管理。必须先定义后台账号、权限、审计和通用交互，供所有业务模块复用。

## 规则

1. 后台管理员必须拥有唯一 `adminUserId`。
2. 管理员必须拥有 `adminRole`；v1.0 唯一可用值为 `super_admin`。
3. 权限必须使用 `permissionKey` 表达，不允许只用 `isSuperAdmin`。
4. 首个 `super_admin` 通过部署期初始化创建，不提供公开管理员注册。
5. 后续管理员账号由已登录超级管理员在后台创建；v1.0 只能创建 `super_admin`，但表单保留 `adminRole` 字段。
6. 管理员账号记录登录标识、显示名称、状态、创建人、创建时间、最后修改人、最后登录时间。
7. 系统必须始终保留至少 1 个启用状态的 `super_admin`。
8. 后台所有页面访问基于 `adminSessionId`，所有写操作基于 `permissionKey`。
9. 管理后台必须提供首页、词库、句库/课程、自动标注、评估配置、用户词库、激活任务、听读练习、课程报告、管理员账号、审计日志入口。
10. 所有敏感写操作必须写入审计日志，审计对象至少包括管理员账号、词条、句子、课程、标注任务、评估配置、用户词库、练习记录、课程报告。

## 交互

- 未登录访问后台 -> 进入后台登录页。
- 超级管理员创建管理员账号 -> 填写登录标识、显示名称、角色，系统生成临时密码、邀请链接或验证码绑定方式。
- 超级管理员禁用账号 -> 系统校验不会禁用最后一个启用超级管理员。
- 管理员进入任一业务模块 -> 使用统一列表、筛选、详情、保存、确认和错误反馈。
- 管理员查看审计日志 -> 可按管理员、对象类型、对象 ID、操作类型、时间筛选。

## 视觉 / UI 布局

- 后台采用工作台布局：左侧导航、顶部账号区、主内容区。
- 列表页提供搜索、筛选、分页、排序、批量选择。
- 详情页按信息分组展示，敏感操作使用二次确认。
- 审计详情使用修改前后摘要对比。

## 边界行为

- 禁用账号不得登录。
- 当前登录管理员不得禁用或删除自己。
- 最后一个启用 `super_admin` 的禁用、删除或降权操作必须被阻止。
- 会话过期后，读页面可保留，写操作必须重新登录。
- 审计日志后台不可编辑、不可删除。

## 验收 checklist

- [ ] 首个超级管理员可通过部署期初始化创建，且无公开注册入口。
- [ ] 超级管理员可创建、启用、禁用、重置后台管理员账号。
- [ ] 系统阻止禁用、删除或降权最后一个启用超级管理员。
- [ ] 后台导航覆盖 v1.0 所有业务模块和审计日志。
- [ ] 所有后台写操作基于 `permissionKey` 校验。
- [ ] 所有敏感写操作进入审计日志。
- [ ] 业务模块复用统一列表、详情、筛选、确认和反馈规则。

## 非目标

- 不做多角色配置 UI。
- 不做 SSO/LDAP/OAuth。
- 不做管理员自助注册。

## 管理后台功能

本模块本身就是管理后台基础能力，向 M2-M10 提供账号、权限、导航、审计、通用交互和后台安全规则。

## 依赖

- 上游：无。
- 下游：M2-M10 的所有后台页面使用本模块的 `adminSessionId`、`permissionKey`、审计和通用交互。

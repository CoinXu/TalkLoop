# Learning Activation v1.0 开发交接说明

## 一句话说明

本次不是在旧版听说练习或旧词库激活上做增量修改，而是以 `docs/PRD/learning-activation-v1/` 为唯一需求源重建 v1.0。旧的 `listening-speaking-v1`、旧词库激活、旧独立管理后台相关实现、数据表和种子数据都要按废弃处理。

## 开发执行原则

1. 以 [overview.md](./overview.md) 为总入口，以 10 个模块 PRD 为实现依据。
2. 不再参考旧 `listening-speaking-v1`、旧 `vocabulary-activation-v0.1`、旧 `admin-console` 文档或看板。
3. 每个学习端功能都必须同步实现对应管理后台能力，不允许只做学习端。
4. 旧代码可以复用局部技术实现，但不能保留旧产品模型、旧路由、旧接口语义和旧数据表作为当前主链路。
5. 所有破坏性数据库动作必须先区分环境：本地/开发/测试可重置；生产或含真实用户数据环境必须先备份、评审、审批，不允许直接 drop。

## 旧内容清理范围

### 代码清理

开发需要全仓搜索并清理旧实现，包括但不限于：

- 旧 `listening-speaking-v1` 相关页面、路由、组件、服务、API、状态管理、i18n 文案。
- 旧学习单元模型、旧 transcript sync、旧 speaking score、旧 home review 的主链路实现。
- 旧 `vocabulary-activation-v0.1` 或旧词库激活实现中与 v1.0 冲突的模型、接口、任务逻辑。
- 旧独立 `admin-console` 中只服务旧学习单元后台的页面和接口；可复用后台壳、权限、审计等基础能力，但要迁移到 M1-M10 统一模型。
- 旧测试、mock、seed、fixture、演示数据中不再符合 v1.0 的内容。

### 数据库和表清理

开发需要给出数据库清理方案，至少包含：

1. 现有表清单：标记“保留/改造/删除/新增”。
2. 删除旧表前先确认是否存在真实用户数据。
3. 本地和开发环境允许直接重置数据库或 drop 旧表。
4. 测试/预发环境应使用迁移脚本清理，并保留回滚或重建步骤。
5. 生产环境不允许直接 drop；若未来已有真实数据，必须先备份、导出、确认无业务依赖，再执行迁移。
6. 旧表删除必须同步删除旧 ORM model、repository、API、migration、seed、mock 和测试依赖。

建议新表按 v1.0 业务对象重新建模，至少覆盖：

- 管理员账号、角色权限、审计日志。
- 词条、词频字段、难度、场景标签、听力陷阱、干扰项、词条音频。
- 句子、课程、场景、句子音频、课程发布状态。
- 自动标注任务、标注结果、审核状态、人工修正历史。
- 评估题、估值矩阵、验证测试轮次、用户评估结果。
- 用户词库、词状态、SRS、跳过、薄弱发音、状态流转历史。
- 单词激活练习记录、每日任务、任务项。
- 听读练习记录、ASR 转写、文本匹配、波形/时长摘要。
- 课程进度、课程报告、用户统计。

## 数据迁移策略

当前建议按“重建”处理，而不是复杂迁移：

- 如果现有环境没有真实用户数据：直接清库重建，导入 v1.0 seed 数据。
- 如果存在测试用户数据：可以丢弃旧学习记录，只保留账号必要字段，重新初始化 v1.0 用户词库。
- 如果存在真实用户数据：暂停清理，先由 PM/Tech Lead/BE 共同确认保留范围，再另开迁移 PRD。

旧学习记录不自动迁移到 v1.0，因为旧模型与 v1.0 的词库、句子、激活状态、课程报告语义不同，强行迁移会制造错误进度。

```text
- docs/PRD/learning-activation-v1/acceptance.md

要求：

2. 清理旧数据库表、ORM model、seed、mock、测试和 API；本地/开发环境可重置数据库。

5. 任何生产或真实数据环境不得直接 drop 表，必须先给出备份和迁移方案。
6. 开发前先输出技术拆解：保留哪些基础代码、删除哪些旧模块、新增哪些表、迁移步骤、风险点。
```

## 风险与约束

- PM 不指定具体 drop SQL，由 BE/Tech Lead 负责迁移脚本和执行环境。
- 任何含真实用户数据的环境，不能用“清理旧表”替代数据迁移评审。
- 若开发发现旧代码中有可复用基础设施，可复用实现细节，但不能保留旧产品语义。

# M5 level-assessment

## 背景 / 要解决的问题

用户首次使用时需要快速建立词汇水平画像。评估不能太重，必须允许用户在 3 题自我描述后立即开始，也提供 2 分钟验证测试提高准确度。

## 规则

1. 首次启动必须完成 3 道自我描述选择题。
2. 前两题用于估算词汇量，第三题只记录听说痛点。
3. 估值矩阵范围为 500-7500 词。
4. 完成自我描述后，不展示精确“词汇量分数”，只提示已准备激活计划。
5. 验证测试为可跳过的非模态提示。
6. 验证测试每轮 5 个词，共 8-10 轮，总计 40-50 个词。
7. 用户只标记“认识/不认识或不确定”，不要求选释义或拼写。
8. 每轮按认识率自适应调整词频难度：`>=80%` 出更难词，`<=30%` 出更简单词。
9. 终止条件为完成 10 轮，或连续 3 轮认识率在 40%-70%。
10. 验证测试结果用于定位词频边界并替换粗估词库。
11. 用户可在“我的”页面重新测试。

## 交互

- 用户首次启动 -> 依次回答使用场景、阅读理解程度、听说困难。
- 自我描述完成 -> 生成粗估词库并进入首页。
- 系统提示快速测试 -> 用户可去测试或先不了。
- 验证测试每轮展示 5 个词 -> 用户点选认识的词 -> 确认进入下一轮。
- 测试完成 -> 展示描述性结果和“开始激活”入口。

## 视觉 / UI 布局

- 自我描述每屏只展示一个问题和 3-4 个选项。
- 验证测试使用可点选词卡，已选状态明确。
- 结果页强调“接下来要练什么”，弱化考试感。
- 后台评估配置页展示题目、选项、估值矩阵、采样策略和版本。

## 边界行为

- 用户跳过验证测试后，使用粗估词库。
- 验证测试中断后，可继续或重新开始，不能生成半成品精确词库。
- 采样词不足时，按实际可用词量降级生成测试。
- 评估配置变更不 retroactively 修改已有用户结果，除非管理员主动重算。

## 验收 checklist

- [ ] 首次启动必须完成 3 题自我描述。
- [ ] 自我描述前两题按矩阵生成估值，第三题只记录痛点。
- [ ] 用户可跳过验证测试并使用粗估词库。
- [ ] 验证测试可在 8-10 轮内完成。
- [ ] 验证测试按认识率自适应调整难度。
- [ ] 验证测试结果可替换粗估词库并重新生成激活计划。
- [ ] 后台可管理自我描述题、估值矩阵、验证测试采样规则和结果版本。

## 非目标

- 不做标准化考试报告。
- 不要求用户输入拼写或释义。

## 管理后台功能

后台必须提供评估题配置、估值矩阵配置、测试采样策略、评估版本管理、用户评估结果查看、重算入口和审计。

## 依赖

- 上游：M1 后台基础；M2 词频分层词表。
- 下游：M6 使用评估结果生成用户词库；M8 使用评估结果展示初始任务。

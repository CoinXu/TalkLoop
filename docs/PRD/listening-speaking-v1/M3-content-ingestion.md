# M3 content-ingestion

## 背景 / 要解决的问题

V1 内容需要可运营。内容进入系统有两条路径：上传文字稿和音频，或从 BBC 页面下载文字稿和音频后整理。导入模块负责把外部素材变成 M1 定义的学习单元草稿，并进入审核和发布。

## 规则

1. 后台必须支持手动上传音频文件。
2. 后台必须支持手动粘贴或上传文字稿。
3. 后台必须支持输入 BBC 页面 URL 发起素材导入，生成草稿单元。
4. URL 导入必须写入 `sourceType=bbc_url_import` 和原始 `sourceUrl`。
5. URL 导入生成的单元默认 `licenseStatus=internal_review` 或 `unknown`，不得默认 `approved`。
6. 导入后运营必须人工确认目标表达、中文释义、目标跟读句和替换说练习。
7. 后台发布前必须通过字段完整性校验：音频、文字稿、目标表达、至少一个目标句、至少一个口语练习。
8. 发布动作只改变 `publishStatus`，不得自动改变 `licenseStatus`。
9. 当 `licenseStatus=unknown` 或 `rejected` 时，系统必须阻止发布。
10. 当 `licenseStatus=internal_review` 时，系统允许发布为内部测试内容，但必须在发布确认中提示“仅内部测试账号可见”。
11. 导入失败要保留失败原因，方便运营判断是页面结构变化、网络失败、音频不可下载还是解析失败。

## 交互

- 运营点击“新建单元” -> 选择“手动上传”或“URL 导入”。
- 运营输入 BBC URL -> 系统抓取可用标题、发布时间、音频、文字稿，生成草稿预览。
- 运营检查预览 -> 可编辑标题、表达、释义、文字稿段落和练习。
- 运营点击“发布” -> 系统做完整性和授权状态校验，通过后单元进入对应可学习范围：`approved` 面向普通用户，`internal_review` 仅面向内部测试账号。

## 视觉 / UI 布局

- 后台页面分为导入区、草稿预览区、发布检查区。
- URL 导入结果必须明确展示来源 URL 和授权状态，不隐藏在折叠面板中。
- 发布按钮旁展示阻塞项数量，例如“还差 2 项才能发布”。

## 边界行为

- BBC 页面无法解析时，允许运营切换为手动上传，不丢失已输入 URL。
- 音频下载失败但文字稿成功时，单元保持草稿，提示补充音频。
- 文字稿过长时，系统允许保存，但提示 V1 单元建议 3-5 分钟。
- 重复导入同一 `sourceUrl` 时，系统提示已有草稿或已发布单元，避免重复内容。
- `licenseStatus=rejected` 的单元不得发布，即使字段完整。
- `licenseStatus=unknown` 的单元不得发布，即使字段完整。

## 验收 checklist

- [ ] 后台支持上传音频和文字稿创建草稿单元。
- [ ] 后台支持 BBC URL 导入并记录来源。
- [ ] URL 导入不会默认授权通过。
- [ ] 发布前会校验 M1 要求的必填字段。
- [ ] `licenseStatus=unknown` 或 `rejected` 的单元不能发布。
- [ ] 导入失败能显示明确失败原因。

## 非目标

- 不承诺兼容 BBC 所有历史页面模板。
- 不做批量爬取和自动发布。
- 不做版权授权自动判断。

## 依赖

- 上游：M1 的 `unitId`、`audioAsset`、`transcriptSegments`、`sourceType`、`sourceUrl`、`licenseStatus`、`publishStatus`。
- 下游：M4 使用 M3 产出的草稿或已发布单元执行音频文字稿同步；M5 只消费 M3 发布后的学习单元。

- 2026-05-02：补充发布前授权状态校验。原因：修复“字段完整即可发布”和授权状态限制之间的潜在冲突；见 conflicts.md/C3。

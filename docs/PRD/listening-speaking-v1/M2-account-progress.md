# M2 account-progress

## 背景 / 要解决的问题

V1 需要账号和数据库，以保存学习进度、单元完成、录音评分和复习入口。账号能力只服务学习闭环，不扩展成社交或会员系统。

## 规则

1. 用户必须拥有唯一 `userId`。
2. V1 必须支持一种验证码登录方式，登录方式由部署配置确定为 `phone_otp` 或 `email_otp`；同一部署环境必须固定一种，QA 按当前配置验证。
3. 登录后系统创建 `sessionId`，H5 使用 `sessionId` 判断是否可保存进度。
4. `unitProgress` 必须记录 `userId`、`unitId`、当前步骤、完成状态、最后学习时间。
5. 完成状态可选值为 `not_started`、`in_progress`、`completed`。
6. `scoreHistory` 必须记录 `scoreId`、`userId`、`unitId`、`scoreTargetType`、评分对象 ID、分数、录音地址、创建时间。
7. 同一用户同一评分对象可有多次评分记录，首页展示最近一次，历史页展示全部。
8. 账号必须记录 `isInternalTester`，用于判断 `licenseStatus=internal_review` 的内容是否可访问。
9. 未登录用户可浏览公开单元并体验到替换说录音前；进入评分提交前必须登录，未登录状态不能保存进度和评分。
10. 账号模块不存储明文密码。

## 交互

- 用户首次进入 H5 -> 可浏览公开单元，点击保存进度、提交评分或访问个人入口时触发登录。
- 用户登录成功 -> 返回原学习步骤，不强制回首页。
- 用户完成单元 -> 系统把 `unitProgress.status` 更新为 `completed`。
- 用户重复练习同一评分对象 -> 系统新增评分记录，不覆盖历史记录。

## 视觉 / UI 布局

- 登录页应轻量，避免中断学习动机；主按钮文案为“登录并保存进度”。
- 个人学习状态只展示必要信息：已学单元数、最近学习、最近评分。
- H5 顶部不做复杂个人中心入口，使用头像或简短账号入口即可。

## 边界行为

- 登录过期时，用户可继续当前播放和录音，但保存评分前要求重新登录。
- 网络失败导致进度保存失败时，页面提示“本次进度未保存”，不伪造完成状态。
- 同一账号多设备同时学习同一单元时，以最新 `updatedAt` 的步骤作为继续学习入口。
- 用户删除录音不在 V1 范围内；若后端保留周期有要求，由 @tech-lead 确认。

## 验收 checklist

- [ ] 用户可以通过当前部署配置的验证码方式登录，并获得可保存学习数据的会话。
- [ ] 单元学习进度能按用户和单元保存。
- [ ] 单元完成状态能被首页读取。
- [ ] 同一评分对象的多次口语评分都能保留历史。
- [ ] 登录过期不会导致用户当前学习页面崩溃。

## 非目标

- 不做第三方社交登录。
- 不做会员、支付、订阅。
- 不做用户关系链、排行榜、打卡分享。

## 依赖

- 上游：无。
- 下游：M5 使用 `userId`、`sessionId`、`unitProgress` 保存学习步骤；M6 使用 `userId` 写入评分记录；M7 使用 `unitProgress`、`scoreHistory` 和 `isInternalTester` 展示可访问内容、继续学习与复习入口。

## 决策记录

- 2026-05-02：V1 需要账号和数据库。原因：用户明确要求账号与数据库，且口语练习必须沉淀多次评分，才能形成复习价值。
- 2026-05-02：明确游客体验只能到评分提交前，评分和进度保存必须登录。原因：修复未登录可体验与评分必须绑定 `userId` 的边界歧义；见 conflicts.md/C2。

# M4 transcript-sync

## 背景 / 要解决的问题

用户要从“听不懂”过渡到“能说出来”，需要把听到的音频和看到的文字稿对齐。同步模块负责将文字稿段落和音频时间轴绑定，支持播放高亮、逐句重听、跟读定位。

## 规则

1. 同步输入必须包含 M1 的 `audioAsset` 和 `transcriptSegments`。
2. 系统应自动生成 `syncedSegments`，每段包含 `segmentId`、开始时间、结束时间、英文文本、中文辅助说明。
3. 自动同步结果必须允许人工校准开始时间和结束时间。
4. 目标跟读句必须绑定到一个或多个 `syncedSegments`。
5. 每个同步段的开始时间必须小于结束时间。
6. 同一音频内同步段不得出现明显交叉；相邻段允许短暂停顿。
7. 同步完成后生成 `syncStatus`，可选值为 `not_synced`、`auto_synced`、`manually_reviewed`。
8. 只有 `syncStatus=auto_synced` 或 `manually_reviewed` 的单元可进入学习主流程。
9. 若目标跟读句绑定的 `segmentId` 在 `syncedSegments` 中不存在，单元不得进入学习主流程。

## 交互

- 运营进入同步页 -> 系统展示音频播放器和文字稿段落。
- 系统自动同步完成 -> 页面按时间轴标记每段文字。
- 运营播放音频 -> 当前段落高亮。
- 运营拖动段落时间点 -> 系统即时更新高亮位置。
- 运营点击“确认同步” -> `syncStatus` 更新为 `manually_reviewed`。

## 视觉 / UI 布局

- 左侧为文字稿段落列表，右侧为音频波形或时间轴。
- 当前播放段落使用明显高亮，但不遮挡文字。
- 每个段落显示开始和结束时间，支持精确到 0.1 秒的调整。

## 边界行为

- 自动同步失败时，允许运营手动逐段打点。
- 段落时间缺失时，学习端不得展示逐句高亮。
- 音频加载失败时，同步页显示文件状态，不允许确认同步。
- 文字稿被 M3 修改后，原 `syncStatus` 退回 `not_synced` 或标记需要复核，具体策略由 @tech-lead 确认。

## 验收 checklist

- [ ] 系统能基于音频和文字稿生成同步段。
- [ ] 运营能人工调整每段开始和结束时间。
- [ ] 播放音频时当前文字段落能高亮。
- [ ] 目标跟读句的 `segmentId` 能定位到对应音频片段。
- [ ] 未同步单元不能进入完整学习流程。

## 非目标

- 不做字幕翻译质量评估。
- 不做逐词级别强制对齐。
- 不做复杂音频剪辑工具。

## 依赖

- 上游：M1 的 `audioAsset`、`transcriptSegments`、`targetSentence`；M3 的草稿和发布前内容。
- 下游：M5 使用 `syncedSegments` 和 `syncStatus` 播放高亮、逐句重听和跟读定位。

## 决策记录

- 2026-05-02：V1 采用段落/句子级同步，不做逐词同步。原因：V1 目标是 H5 快速验证说的闭环，逐词同步成本高且不是核心验收。
- 2026-05-02：补充目标句 `segmentId` 必须能在同步段中定位。原因：修复 M5 跟读定位的数据流闭合问题；见 conflicts.md/C4。

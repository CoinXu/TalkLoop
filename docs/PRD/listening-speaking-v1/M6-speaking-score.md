# M6 speaking-score

## 背景 / 要解决的问题

用户不需要系统纠错，而是需要一个轻量评分和可回放对比机制，帮助自己判断跟示范音频的差距。评分模块负责录音、提交、分数展示、示范对比和历史保存。

## 规则

1. 评分输入必须包含 `userId`、`unitId`、评分对象类型 `scoreTargetType`、评分对象 ID、用户录音、目标文本、示范音频片段或参考答案。
2. `scoreTargetType` 可选值为 `target_sentence`、`speaking_prompt`；`target_sentence` 使用 `targetSentenceId`，`speaking_prompt` 使用 `speakingPromptId`。
3. 评分输出必须包含总分 `overallScore`，范围 0-100。
4. V1 可展示维度分：发音相似度、流利度、完整度；不展示逐词纠错。
5. 系统不得自动生成“你应该改哪里”的纠错说明。
6. 评分结果页必须提供用户录音回放和示范音频或参考答案回放/展示。
7. 每次评分都写入 M2 的 `scoreHistory`，不覆盖旧记录。
8. 只有 `scoreTargetType=speaking_prompt` 的有效评分可触发单元完成。
9. 评分失败时不得写入完成状态。

## 交互

- 用户点击录音 -> 页面显示录音状态和时长。
- 用户结束录音 -> 可试听自己的录音，也可重新录。
- 用户提交评分 -> 页面显示评分中。
- 系统返回分数 -> 展示总分、维度分、示范或参考答案、我的录音播放、再练一次。
- 用户点击再练一次 -> 回到录音状态，提交后新增一条评分历史。

## 视觉 / UI 布局

- 评分页中心展示大号总分，维度分放在下方。
- 示范音频和我的录音使用并列播放控件，便于用户对比。
- 不使用红色错误样式表达低分，避免把“评分”误解为“纠错惩罚”。

## 边界行为

- 录音时长低于 1 秒时，不允许提交评分。
- 录音时长超过目标句音频 3 倍时，提示用户重新录制。
- 评分服务超时，页面允许重试，不丢失本地录音。
- 麦克风权限缺失时，展示开启权限提示。
- 评分低于任何分数阈值都不阻止完成；V1 完成标准是替换说练习完成一次有效评分，不是达到高分。

## 验收 checklist

- [ ] 用户可以录音、试听、重录和提交评分。
- [ ] 评分返回总分和维度分。
- [ ] 评分页提供示范音频或参考答案，并提供用户录音回放对比。
- [ ] `target_sentence` 评分不会单独触发单元完成，`speaking_prompt` 有效评分会触发单元完成。
- [ ] 系统不提供逐词纠错和改正建议。
- [ ] 多次评分均能进入评分历史。

## 非目标

- 不做 AI 语法批改。
- 不做逐词音素纠错。
- 不做真人老师点评。
- 不做强制达标才能过关。

## 依赖

- 上游：M1 的目标文本、示范音频片段、`targetSentenceId`、`speakingPromptId`；M2 的 `userId` 和 `scoreHistory`；M5 的录音任务、评分对象类型、评分对象 ID、录音文件。
- 下游：M7 使用 M6 的最近评分和评分历史展示复习入口。

## 决策记录

- 2026-05-02：V1 只做评分不做纠错。原因：用户明确表示想学的用户会自己对比发音和音频差异，产品不应把复杂纠错作为首版负担。
- 2026-05-02：评分对象拆为 `target_sentence` 和 `speaking_prompt`，只有替换说评分可完成单元。原因：修复 M5/M6 评分对象和完成条件不一致；见 conflicts.md/C1。

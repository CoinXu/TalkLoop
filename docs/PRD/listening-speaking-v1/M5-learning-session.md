# M5 learning-session

## 背景 / 要解决的问题

学习主流程要把内容变成可完成的 3-5 分钟口语训练。V1 不是泛听播放器，而是引导用户从听原音、看文字、跟读，到在新场景中说出目标表达。

## 规则

1. 学习流程必须围绕单个 `unitId`。
2. 单元入口必须展示目标表达、中文释义、场景说明和预计时长。
3. 学习步骤固定为：听原音、看文字精听、目标句跟读、替换说、评分结果。
4. 用户必须在替换说步骤完成至少一次有效评分，单元才可标记为 `completed`。
5. 听原音步骤默认不显示完整文字稿，只显示目标表达和播放控制。
6. 看文字精听步骤展示同步高亮文字稿，允许逐句重听。
7. 跟读步骤使用 M4 的目标句时间段播放示范音频，可进行过程评分，但过程评分不单独触发单元完成。
8. 替换说步骤必须给出中文场景和必要英文提示，但不直接展示完整期望答句，除非用户主动查看参考答案。
9. 用户退出学习页时，系统保存当前步骤到 M2 的 `unitProgress`。
10. 学习端只消费 `publishStatus=published`、当前用户有访问权限、且 `syncStatus=auto_synced` 或 `manually_reviewed` 的单元。

## 交互

- 用户点击单元 -> 进入目标表达页，点击开始。
- 用户听完整音频 -> 进入文字精听，可点任一段重听。
- 用户进入跟读 -> 点击示范音频，再按住或点击录音完成跟读，可选择提交跟读评分。
- 用户进入替换说 -> 看中文场景后录音说出答案。
- 用户在替换说步骤提交录音 -> 进入 M6 评分，评分返回后展示结果和回放。
- 用户完成单元 -> 首页显示已完成和最近评分。

## 视觉 / UI 布局

- H5 首屏以学习任务为主体，底部固定主操作按钮。
- 播放器、录音按钮、下一步按钮必须适合单手操作。
- 文字稿区域使用逐段卡片或列表，不做大段文章阅读排版。
- 替换说页面突出“场景”和“录音”，弱化解释文字。

## 边界行为

- 音频播放失败时，用户不能进入跟读和替换说，页面提示重试。
- 录音权限被拒绝时，页面说明需要开启麦克风权限，单元不可完成。
- 用户跳过听原音或精听步骤时，允许继续，但完成单元仍需要一次评分。
- 未登录用户提交评分前触发登录；登录成功后回到原步骤并继续提交。
- 网络中断时，本地可继续播放已缓存音频，但评分提交失败需重试。

## 验收 checklist

- [ ] 用户可以按固定步骤完成一个单元。
- [ ] 学习流程以替换说步骤至少一次有效评分作为完成条件。
- [ ] 文字稿能跟随音频同步高亮。
- [ ] 替换说练习不会默认展示完整答案。
- [ ] 用户退出后再次进入能继续上次步骤。

## 非目标

- 不做自由对话。
- 不做长篇课程学习路径。
- 不做复杂学习计划和日历。

## 依赖

- 上游：M1 的 `unitId`、目标表达、文字稿、目标句、替换说练习；M2 的 `userId`、`sessionId`、`unitProgress`；M4 的 `syncedSegments`。
- 下游：M6 使用 M5 产生的录音任务、评分对象类型、`targetSentenceId` 或 `speakingPromptId`、用户录音；M7 使用 M5 写入的完成状态展示继续学习。

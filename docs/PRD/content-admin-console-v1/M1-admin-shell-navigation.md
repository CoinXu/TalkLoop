# M1 admin-shell-navigation

## 背景 / 要解决的问题

内容后台首版只面向超级管理员，但仍需要统一入口、导航、列表、详情、批量操作、确认弹窗和反馈规则。否则场景、课程、句子池、导入和发布校验会各自实现不同交互，降低运营效率。

## 规则

1. 后台入口仅对超级管理员开放；非超级管理员访问时展示无权限页，不展示内容数据。
2. 一级导航包含：场景管理、课程管理、句子池、批量导入、发布校验/任务结果。
3. 所有列表页必须支持分页、关键词搜索、筛选区、批量选择、列显示主要状态和更新时间。
4. 所有批量操作必须先展示确认弹窗，弹窗说明影响对象数量、目标状态和不可操作对象数量。
5. 批量操作完成后必须展示成功、失败、跳过数量，并允许查看失败原因。
6. 所有状态变更、批量导入、课程编排保存必须写入审计字段：操作者、时间、操作类型、对象 ID、变更摘要。
7. 详情页必须提供返回列表时保留筛选、分页和滚动位置的能力。
8. 破坏性操作包括归档、从课程移除句子、批量覆盖课程归属，必须二次确认。

## 交互

- 超级管理员进入后台 -> 默认进入内容概览页，看到场景数、课程数、未分配句子数、可发布课程数、发布校验失败项。
- 超级管理员在任意列表选择多项 -> 点击批量操作 -> 系统弹出确认 -> 执行后展示结果摘要。
- 超级管理员从列表进入详情 -> 修改并保存 -> 系统提示成功并保留在详情页。
- 超级管理员执行失败操作 -> 系统展示可读错误原因，并保留当前编辑内容。

## 视觉 / UI 布局

- 后台采用工作台式布局：左侧固定导航，顶部展示当前模块标题和主操作按钮，主体为筛选区、表格和详情抽屉/页面。
- 列表页优先展示可扫描信息：名称/文本、状态、归属、音频状态、更新时间、操作。
- 批量操作栏在选择对象后固定显示，避免滚动后丢失上下文。
- 状态使用稳定颜色和文字，不只依赖颜色区分。

## 边界行为

- 列表为空时展示空态和可执行的下一步操作，例如新建场景或导入句子。
- 筛选无结果时保留筛选条件，并提供清空筛选入口。
- 批量操作中存在不可操作对象时，不阻塞可操作对象，但必须展示跳过原因。
- 网络或服务异常时，不清空用户已填写内容。

## 验收 checklist

- [ ] 超级管理员可访问内容后台，非超级管理员不可访问。
- [ ] 后台导航覆盖场景、课程、句子池、批量导入、发布校验/任务结果。
- [ ] 列表页具备分页、搜索、筛选、批量选择和状态列。
- [ ] 批量操作结果展示成功、失败、跳过数量和失败原因。
- [ ] 关键变更写入审计字段。
- [ ] 从详情返回列表时保留筛选和分页状态。

## 非目标

- 不做多角色权限配置 UI。
- 不做细粒度菜单授权。
- 不做独立审计日志查询中心。

## 依赖

- 上游：无。
- 下游：M2-M9 使用 M1 的后台通用导航、列表、详情、确认弹窗、批量反馈和审计字段规则。

# M9 admin-api-requirements

## 背景 / 要解决的问题

现有句子管理 API 只有最低 CRUD，无法支撑完整后台。需要汇总 M2-M8 的后台 API 能力，给后端实现提供产品级接口需求。本文不定义数据库结构和具体技术实现。

## 规则

1. API 必须服务超级管理员后台，所有写操作必须校验超级管理员身份。
2. API 响应必须包含可展示的错误原因，支持批量操作的行级或对象级失败原因。
3. 列表 API 必须支持分页、排序、关键词和模块定义的筛选条件。
4. 详情 API 必须返回基础字段、状态、引用信息、最近更新时间和发布校验摘要。
5. 批量 API 必须返回成功、失败、跳过数量，以及失败对象 ID 和原因。
6. 发布校验 API 必须支持单对象和批量对象校验。
7. 课程编排 API 必须支持添加、移除、排序移动、批量分配课程。
8. 批量导入 API 必须支持上传解析、字段映射预校验、确认导入、结果查询、失败行下载。
9. API 命名、路由、鉴权中间件、事务策略由 @be-dev / @tech-lead 确认。

## 交互

- 前端请求场景、课程、句子列表 -> API 返回分页数据和筛选结果。
- 前端请求句子详情 -> API 返回归属、音频、引用和校验摘要。
- 前端提交课程编排 -> API 保存 `sceneId`、`courseId`、`sortOrder` 并返回校验摘要。
- 前端提交批量发布 -> API 逐项校验并返回结果。
- 前端执行导入流程 -> API 按上传、预校验、确认导入、结果查询分步响应。

## 视觉 / UI 布局

本模块不直接定义 UI。API 返回的数据必须支持 M1-M8 中定义的列表、详情、校验弹窗、导入步骤和批量结果展示。

## 边界行为

- 批量接口部分失败时，不应让前端只能得到通用错误；必须返回对象级原因。
- 发布校验接口不应直接修改状态，除非调用的是明确的发布接口。
- 课程排序移动失败时，API 需返回当前服务端顺序，便于前端恢复。
- 导入任务中断时，结果查询 API 需返回明确状态：处理中、成功、部分成功、失败。

- [ ] 提供课程列表、详情、创建、编辑、状态变更、排序 API 需求。
- [ ] 提供句子列表、详情、创建、编辑、归档、完整筛选 API 需求。
- [ ] 提供批量导入、预校验、确认导入、失败行下载 API 需求。
- [ ] 提供批量发布、下架、归档、恢复草稿 API 需求。

- [ ] 所有批量 API 返回对象级失败原因。

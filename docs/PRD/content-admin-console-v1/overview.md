# Content Admin Console v1 产品概述

## 背景

当前后端已有最低限度的句子 CRUD 管理 API，但还不足以支撑真实内容运营。70,760 条已导入句子目前更接近“句子池”，多数尚未关联场景、课程和课程内排序，也缺少批量导入、批量状态更新、批量编排、课程发布校验和句子详情等后台闭环。

本需求规划一个面向超级管理员的内容管理后台，用于把句子池转化为可发布的场景、课程和学习端内容。首版强调“可编排、可批量处理、可发布校验、可回滚到下架/归档状态”，不做多角色权限和审核流。

## 首版用户与目标

- 后台用户：超级管理员。
- 核心目标：超级管理员可以管理场景、课程、句子池、课程句子编排、批量导入、批量状态变更、默认音频兜底和发布前校验。
- 达成标志：学习端可以按场景 -> 课程 -> 句子读取已发布内容；后台可以解释每个句子的课程归属、排序、音频状态、发布状态和不可发布原因。

## 首版状态模型

内容对象包含场景、课程、句子。首版统一使用运营状态，不包含审核流。

- `draft`：草稿，可编辑，不进入学习端。
- `published`：已发布，进入学习端可见范围。
- `unpublished`：已下架，不进入学习端，但保留历史引用。
- `archived`：已归档，默认列表隐藏，不允许再次直接发布，需先恢复为草稿。

决策：首版不做 `pending_review` / `approved` / `rejected`。原因是当前只有超级管理员，审核流会增加状态分支和后台复杂度；内容质量先通过发布前校验和人工编辑承担。

## 模块依赖

- M1 输出后台通用列表、详情、确认弹窗、批量操作反馈和状态提示规则，供 M2-M9 使用。
- M2 输出 `sceneId`、场景排序、场景状态和学习端可见规则，供 M3、M4、M6、M8、M9 使用。
- M3 使用 M2 的 `sceneId` 创建课程，输出 `courseId`、课程句子数规则、课程排序、解锁规则和课程状态，供 M4、M6、M8、M9 使用。
- M4 输出句子字段、句子详情、引用信息、筛选条件和句子状态，供 M5、M6、M7、M8、M9 使用。
- M5 使用 M4 的句子字段定义执行批量导入和预校验，输出新增/更新句子结果和失败行，供 M4 列表展示和 M6 编排使用。
- M6 使用 M2 的 `sceneId`、M3 的 `courseId` 和 M4 的句子池，将句子写入课程时同时确定 `sceneId`、`courseId`、`sortOrder`，输出课程内句子列表供 M8 校验和学习端读取。
- M7 使用 M4 的句子音频字段和 M3 的课程发布条件，输出默认音频兜底策略和音频完整性状态，供 M8 发布校验使用。
- M8 使用 M2-M7 的状态、归属、排序、音频和课程规则，统一执行发布、下架、归档、恢复草稿和批量状态变更。
- M9 使用 M2-M8 的字段和操作规则，汇总给后端实现管理 API，不直接定义数据库结构。

## 首版包含

- 场景管理：列表、新建、编辑、排序、发布/下架/归档。
- 课程管理：按场景展示课程，新建课程，维护 level、描述、课程句子数规则、解锁规则、排序、发布状态。
- 句子池：完整筛选、详情、编辑、归档、引用查看、音频状态查看。
- 批量导入：CSV/JSON 上传、字段映射、预校验、失败行下载。
- 批量运营：批量发布、下架、归档、恢复草稿、批量分配场景/课程、批量排序。
- 课程编排：左侧句子池，右侧课程句子列表，支持添加、移除、拖拽排序。
- 发布校验：句子数规则、音频兜底、目标词、难度一致性、课程归属、场景状态。
- 默认音频：允许超级管理员配置或使用系统默认音频作为缺失音频兜底；发布校验需明确展示哪些句子使用默认音频。
- 管理 API：补齐列表筛选、详情、批量导入、批量状态、批量分配、课程内排序/移动、归档接口。

## 首版不包含

- 多角色权限配置 UI。
- 审核流、待审核队列、审核员角色、审核意见。
- 自动生成真实音频或 TTS 任务编排。
- 在线表格级 Excel 编辑器。
- 用户自建课程。
- 学习端 UI 改版；本期只保证学习端能读取已发布内容结构。

## 决策记录

- 2026-05-04：首版后台用户限定为超级管理员。原因：先完成内容生产闭环，暂不引入多角色权限复杂度。
- 2026-05-04：首版不做审核流，仅做草稿、发布、下架、归档等运营状态。原因：用户明确调整范围，审核流留作后续。
- 2026-05-04：课程句子数不固定。原因：用户确认不同课程可有不同句子数，因此句子数作为课程级规则进入发布校验。
- 2026-05-04：默认音频作为可发布兜底。原因：用户会提供默认音频，后台需透明展示兜底使用情况。
- 2026-05-04：M9 作为统一 API 汇总模块依赖 M2-M8。原因：避免每个业务 PRD 重复写接口规则，便于 BE 统一拆接口。
- 2026-05-04：默认音频允许课程发布，但发布前必须展示使用默认音频的句子数量和列表。原因：保证首版可发布，同时让内容质量风险对超级管理员透明。
